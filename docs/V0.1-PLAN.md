# V0.1 plan: foundation and keyword intelligence

Goal: a working, honest keyword-intelligence tool for Hunter Vault, built on a multi-app
foundation. Smaller and solid beats broad and half-finished.

## Scope

In scope:

- Next.js 16 (App Router, TypeScript strict, Tailwind v4, shadcn/ui on Radix, Lucide icons)
- Supabase (Postgres + Auth), schema `aso`, migrations, RLS, dev seed
- Workspaces, members (roles), apps, store listings
- Onboarding: create workspace, then add app (iOS and/or Android)
- Overview dashboard: tracked keywords, top 10/50, improved/declined, Estimated Search Visibility,
  ranking distribution, ASO Health checklist, top opportunities, recent changes
- Keyword intelligence table: search, filters, sorting, bulk actions, add/remove, pause/resume tracking
- Keyword detail: rank and popularity history, movement, difficulty, opportunity breakdown,
  metadata coverage, top results, related ASO events
- Opportunity Score domain module (`opportunity_v1`)
- Estimated iOS rank via Apple's public iTunes Search API, with append-only history
- Estimated difficulty from the same search results
- Android rank provider contract, returning `unsupported`
- Apple Ads popularity provider: `not_configured` without credentials; manual popularity entry
- Metadata coverage analyzer
- ASO change timeline (`/dashboard/experiments`)
- Settings: app details, listings (manual metadata editing, iOS sync from App Store), integration
  status, workspace info
- Scheduler-ready collector and a protected job endpoint
- Tests for the domain logic, plus README and docs

Explicitly out of scope (later versions):

- App Store Connect / Google Play reporting (V0.2)
- Competitor discovery and monitoring (V0.3; tables exist)
- Review intelligence (V0.4)
- Before/after experiment analysis (V0.5)
- AI analyst and recommendations (V0.6)
- Team invitations and billing (V1)
- Any automatic publishing to stores (never without explicit manual approval)

## Database model

See [ARCHITECTURE.md](./ARCHITECTURE.md#database) for the table list. Migrations:

| Migration | Contents |
|---|---|
| `…_aso_schema_and_tenancy.sql` | Schema, enums, `workspaces`, `workspace_members`, `apps`, `store_listings`, `metadata_snapshots`, helper functions, `create_workspace` RPC, `updated_at` triggers, listing snapshot trigger |
| `…_aso_keywords_and_history.sql` | `keywords`, `keyword_rank_history`, `keyword_popularity_history`, `keyword_difficulty_history`, `collector_runs`, append-only guard trigger, `keyword_overview` view |
| `…_aso_competitors_and_events.sql` | `competitors`, `competitor_snapshots`, `aso_events` |
| `…_aso_rls_and_grants.sql` | RLS policies for every table and grants for `authenticated` / `service_role` |

Seed (`supabase/seed.sql`, local only; `supabase db push` never runs it):

- Dev user `dev@aso.local` / `aso-dev-password`
- Workspace **Hunter Vault** → app **Hunter Vault** → iOS listing (App Store ID `6761086056`,
  bundle `com.hunter.vault`, US, en). No metrics are seeded; rankings come from real checks.
- Workspace **Demo workspace** (`is_demo = true`) → app **Budget Quest (demo)** with synthetic
  history (`source = demo`), shown under a "Demo data" banner. It exists to preview charts before
  real history accumulates.

## Implementation sequence

1. Scaffold: Next.js, TypeScript strict, Tailwind, shadcn, ESLint/Prettier, Vitest, env validation
2. Supabase config, migrations, RLS, seed; generate types from the local database
3. Domain logic and tests (`src/lib/aso`): normalization, rank semantics, coverage, difficulty,
   opportunity, visibility, health, scheduling
4. HTTP utilities (timeout, retry, backoff, rate limiter) and store providers (Apple iTunes rank +
   metadata, Apple Ads popularity, Google Play unsupported), registry, provider tests with fixtures
5. Supabase clients, proxy, auth pages, auth helpers
6. Workspace and app context (active app cookie), onboarding, add app (with iOS metadata import)
7. Dashboard shell: sidebar, app switcher, theme toggle, demo banner, "Coming next" pages
8. Keywords: data access, add/remove/track actions, table (desktop) and list (mobile), filters
9. Rank collection: collector service, refresh action (batched, with progress), cron endpoint
10. Keyword detail: rank history chart with ranges and event annotations, popularity history and
    manual entry, movement table, coverage, opportunity breakdown, top results
11. ASO events timeline: record and delete events
12. Overview dashboard
13. Settings: app, listings (edit metadata, sync), integrations status, workspace
14. Loading, error, empty and not-found states throughout
15. README, then lint, typecheck, tests and production build, fixing everything

## Acceptance checks

- `npm run lint`, `npm run typecheck`, `npm test` and `npm run build` all pass.
- Migrations apply cleanly with `supabase db reset`, and generated types match the schema.
- A new user can sign up, create a workspace and add an app, then add keywords and refresh rankings.
- Every rank from the iTunes source is labelled "Estimated Rank". Unranked results read `>N` (the
  largest threshold the returned results prove) or "Not found", and are never plotted as numbers.
- With no Apple Ads credentials, popularity reads "Apple keyword popularity not connected" and
  nothing breaks.
- Metrics without data show an explicit empty state. Nothing is fabricated outside the demo workspace.
